# 阶段六可行性探索：玻璃机壳包覆铜水管

> 日期：2026-08-29
> 目的：研读 Create 原版水管包覆相关源码，确认玻璃/透明/照明机壳包覆铜水管的技术可行性与实现方案

## 二、核心结论

### 2.1 技术可行性：确认可行

`FluidPipeBlock` 实现了 `EncasableBlock` 接口，通过 `EncasingRegistry.addVariant()` 注册包覆变体，与轴/齿轮注册方式完全一致。子类继承 `EncasedPipeBlock` 即可复用全部水管逻辑。

### 2.2 BlockEntity 复用：自动通过

`FluidPipeBlockEntity` 内部有两处关键 instanceof 检查：

1. `canHaveBracket()`：`return !(state.getBlock() instanceof EncasedPipeBlock)` — 包覆水管不能有支架，继承 `EncasedPipeBlock` 自动通过
2. `canHaveFlowToward()`：`state.getBlock() instanceof EncasedPipeBlock` — 判断流体能否流向该方向，继承自动通过
3. `getRenderedRimAttachment()`：`state.getBlock() instanceof EncasedPipeBlock` — 包覆水管不渲染 Rim 附件，继承自动通过

**子类需要覆写 `getBlockEntityType()`**，因为 `EncasedPipeBlock` 硬编码返回 `AllBlockEntityTypes.ENCASED_FLUID_PIPE.get()`，需指向自己的 BlockEntity 注册。

### 2.3 包覆/拆包覆流程：完全复用

`EncasedPipeBlock.handleEncasing()` 负责包覆时的状态转移：
1. `FluidTransportBehaviour.cacheFlows()` — 缓存当前流体流动
2. `transferSixWayProperties()` — 将铜水管的六向连接状态转移到包覆水管
3. `FluidTransportBehaviour.loadFlows()` — 恢复流体流动

`onWrenched()` 负责扳手拆包覆，流程类似，恢复为 `AllBlocks.FLUID_PIPE`。

这两个方法不需要覆写，子类继承即可。

### 2.4 渲染机制的深层问题

#### blockstate/模型 JSON（可替换）

`BlockStateGen.encasedPipe()` 生成 multipart blockstate，共 12 个 part（6 方向 × 2 模型）：

- **block_flat**（封闭面，连接=false）：引用 `create:block/copper_casing` 贴图
- **block_open**（开口面，连接=true）：引用 `create:block/encased_pipe` 贴图

这两个模型 JSON 只有一个薄面板元素（z=15~16），贴图引用可以通过自定义 JSON 替换为透明机壳贴图，与轴/齿轮包覆的贴图替换方式一致。

#### PipeAttachmentModel 的 FLUID_PIPE_CASING（不可直接替换）

`PipeAttachmentModel` 是动态管道渲染器，在基础模型四边形之上额外附加：

1. 支架模型（bracket）— 不涉及
2. 六向管道连接附件（`AllPartialModels.PIPE_ATTACHMENTS`）— 不涉及
3. **机壳 3D 外壳**（`AllPartialModels.FLUID_PIPE_CASING`）— 仅当 `shouldDrawCasing()` 为 true 时渲染

`shouldDrawCasing()` 判断逻辑：方块是 pipe 且某轴上有 >2 个连接方向时，返回 true（即交叉/多向连接处显示 3D 外壳）。

**关键问题**：`FLUID_PIPE_CASING` 是 `AllPartialModels` 中的固定条目，其贴图（`create:block/copper_casing`）无法通过 blockstate/模型 JSON 替换。这意味着：

- 方案 A（仅替换面板贴图）：接受 3D 外壳仍为铜色，只将 block_flat/block_open 面板替换为透明贴图。实现简单，但 3D 外壳不透明，与轴/齿轮包覆的完全透明效果不一致。
- 方案 B（自定义渲染器）：编写自定义 BakedModel wrapper 继承 `PipeAttachmentModel`，在渲染时将 FLUID_PIPE_CASING 的贴图替换为透明版本。实现复杂，但能达到完全透明。

此方案选择待用户确认。

### 2.5 原版注册链参考

Create 原版 `AllBlocks.ENCASED_FLUID_PIPE` 注册链：

```java
REGISTRATE.block("encased_fluid_pipe", p -> new EncasedPipeBlock(p, AllBlocks.COPPER_CASING::get))
    .initialProperties(SharedProperties::copperMetal)
    .properties(p -> p.noOcclusion().mapColor(MapColor.TERRACOTTA_LIGHT_GRAY))
    .transform(axeOrPickaxe())
    .blockstate(BlockStateGen.encasedPipe())
    .onRegister(CreateRegistrate.connectedTextures(() -> new EncasedCTBehaviour(AllSpriteShifts.COPPER_CASING)))
    .onRegister(CreateRegistrate.casingConnectivity((block, cc) -> cc.make(block, AllSpriteShifts.COPPER_CASING,
        (s, f) -> !s.getValue(EncasedPipeBlock.FACING_TO_PROPERTY_MAP.get(f)))))
    .onRegister(CreateRegistrate.blockModel(() -> PipeAttachmentModel::withAO))
    .loot((p, b) -> p.dropOther(b, FLUID_PIPE.get()))
    .transform(EncasingRegistry.addVariantTo(AllBlocks.FLUID_PIPE))
    .register();
```

本项目参照轴/齿轮包覆的模式，需要适配的关键差异：
- 初始属性：参照 `GlassEncasedShaft` 用 `Blocks.GLASS`（玻璃版）或 `Blocks.GLOWSTONE`（照明版）
- 透光属性：覆写 `propagatesSkylightDown` 和 `getShadeBrightness`（参照 `GlassEncasedShaft`）
- 渲染层：玻璃版 `cutout`，透明玻璃版 `cutout`，照明版 `translucent`
- CT 行为：使用 `GlassEncasedCTBehaviour` / `IlluminationEncasedCTBehaviour`
- 机壳连接性：`casingConnectivity` 的 `(s, f)` 判断与原版一致（连接方向不连接 CT）
- blockstate：不能直接用 `BlockStateGen.encasedPipe()`（会引用原版模型路径），需手写 multipart blockstate 或自定义生成逻辑
- blockModel：需注册 `PipeAttachmentModel` 以支持动态管道连接渲染

### 2.6 BlockEntity 注册

原版 `AllBlockEntityTypes.ENCASED_FLUID_PIPE` 注册：

```java
REGISTRATE.blockEntity("encased_fluid_pipe", FluidPipeBlockEntity::new)
    .validBlocks(AllBlocks.ENCASED_FLUID_PIPE)
    .register();
```

本项目需注册复用 `FluidPipeBlockEntity` 的 BlockEntity，指向 12 个新方块。需注意 `FluidPipeBlockEntity` 的构造函数签名是 `(BlockEntityType<?>, BlockPos, BlockState)`，与 `SmartBlockEntity` 一致。

### 2.7 资源文件需求

| 资源类型 | 数量 | 说明 |
|----------|------|------|
| blockstate JSON | 3 | 玻璃/透明玻璃/照明各一个 multipart blockstate |
| 模型 JSON (block_flat) | 3 | 封闭面模型，贴图引用对应透明机壳贴图 |
| 模型 JSON (block_open) | 3 | 开口面模型，贴图引用对应开口贴图 |
| 语言文件条目 | 24 | en_us + zh_cn 各 12 个方块名 |
| mineable 标签 | 2 | pickaxe + axe（或复用 `axeOrPickaxe`） |
| 战利品表 | 12 | 掉落铜水管 |
| 开口贴图 | 待定 | 玻璃风格的 `encased_pipe` 贴图变体 |

### 2.8 不支持的包覆类型

| 类型 | 原因 | 后续方向 |
|------|------|----------|
| 玻璃直管包覆 | `AxisPipeBlock.useItemOn()` 硬编码检查铜机壳，不走 EncasingRegistry | 需 Mixin |
| 动力泵包覆 | `PumpBlock` 未实现 `EncasableBlock` | 需从零设计 |
