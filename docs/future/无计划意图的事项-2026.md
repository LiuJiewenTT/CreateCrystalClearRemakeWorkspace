## 1. 小齿轮包覆箱模型替换

**日期**：2026-08-26

**来源**：commit `e94d013`（引入 Create 大包覆齿轮箱模型时的提交备注），原记录于未来参考选用事项 #1，后转移至此

**原意图**：

原本考虑过用 Create 原版小齿轮包覆箱模型直接替换本项目当前的模型。经评估后决定不替换，转移至此。

**背景**：

当前项目的小齿轮包覆箱模型（`encased_cogwheel/` 目录）同样是从 Create 原版提取并改造的——并非纯自建 3D 几何，而是基于 Create 原版模型调整了纹理变量名（原版用 `#side`/`#1`/`#4`，本项目改为 `#siding`/`#backing`/`#opening`）。

大齿轮包覆箱（`encased_large_cogwheel/`）也是从 Create 原版提取并改造的。由于大齿轮原版使用 32×32 的 `side_connected` CT 精灵表，而本项目改用 16×16 独立大齿轮贴图，两者贴图区域设定不同，不能直接复用原版 UV，因此大齿轮的 UV 是在本项目中重新调整的。

**不改的原因**：

1. **视觉一致性已满足**：小齿轮包覆箱当前模型已经是从 Create 原版改造而来，与 Create 原版风格一致，没有替换的必要。即便真的可以替换，也没有改的必要。
2. **独立模型的接口层作用**：本项目将模型从 Create 原版提取后独立维护，相当于一个"接口层"——Create 原版模型中的纹理变量名（`#side`、`#1`、`#4` 等）如果将来发生变化，只需在提取改造时适配一次，不影响本项目所有派生子模型的变量引用。如果直接引用 Create 原版模型，则原版每次变量改名都会波及所有派生物品。保持独立模型（小齿轮和大齿轮各自一套）提供了隔离层。
3. **大齿轮已经验证可行**：大齿轮包覆箱的独立模型 + UV 调整已经完成并验证正常，说明这条路可行。小齿轮如果当前显示正常，就没有必要再动。

**当前状态**：

小齿轮包覆箱仍使用 `encased_cogwheel/` 目录（从 Create 原版提取并改造纹理变量名）。大齿轮包覆箱使用 `encased_large_cogwheel/` 目录（从 Create 原版提取，改造纹理变量名 + 调整 UV 适配 16×16 独立贴图）。两者均已正常工作，不打算再改。
