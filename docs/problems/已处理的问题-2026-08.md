**文件**：`src/main/java/.../registry/builders/GlassBlockBuilders.java`

## 10. 构建依赖引入了无关 mod（炽海生机）

**日期**：2026-08-23

1. `build.gradle` 中删除 `nether-depths-upgrade` 和 `geckolib` 两行 `localImplementation` 依赖
2. `gradle.properties` 中删除 `nether_depths_upgrade_version` 和 `geckolib_version` 两个版本号定义

编译验证通过。5 个炽海生机相关战利品表（`centrifugal_pump`、`copper_tap`、`fluid_interface`、`pipette`、`smart_fluid_interface`）保留不删除，因为它们不会在运行时被加载（无对应方块注册），且属于潜在问题 #8 的跟踪范围。

## 12. 大齿轮 blockFolder 与手写 JSON parent 路径不一致

**日期**：2026-08-25

**问题描述**：`GlassBlockBuilders.java` 中大齿轮的 builder 代码设置 `blockFolder = large ? "encased_large_cogwheel" : "encased_cogwheel"`，但手写 JSON 的 parent 路径统一引用 `encased_cogwheel/` 目录。资源目录中只有 `encased_cogwheel/`，`encased_large_cogwheel/` 从未存在（上游 LoneStarFateZero/CreatePrism 也没有）。若未来运行 datagen 重新生成资源，代码中的 `blockFolder` 设置会导致找不到父模型而出错。

经分析确认：大齿轮和小齿轮共用同一套 `encased_cogwheel/` 父模型（`block.json`、`block_top.json`、`block_bottom.json`、`block_top_bottom.json`、`item.json`），3D 几何完全一致，区别仅在于 siding 贴图（大齿轮用 `large_*_encased_cogwheel_side`）。

**修复**：将 `GlassBlockBuilders.java` 中 4 处 `blockFolder = large ? "encased_large_cogwheel" : "encased_cogwheel"` 统一改为 `blockFolder = "encased_cogwheel"`，保留注释说明大小区别仅在 siding 贴图。暂时没有想到需要保留这个差异的需求来源情景。

**提交**：`edef295`

**文件**：`src/main/java/io/liujiewentt/crystal_clear/registry/builders/GlassBlockBuilders.java`（4 处修改，分别在第 199、213、263、277 行附近）

## 13. illumination 包覆齿轮侧面贴图路径不一致

**日期**：2026-08-25

**问题描述**：`GlassBlockBuilders.java` 中 `getIlluminationSiding()`（第 394-397 行）和 `getIlluminationCogCTBehaviour()`（第 351-356 行）引用 `{material}_illumination_encased_cogwheel_side` 贴图路径，但所有 32 个 illumination 齿轮模型 JSON 手写引用的是 `{material}_encased_cogwheel_side`（不带 illumination），两者路径不匹配。导致 illumination 齿轮的 CT 连接效果实际未生效。若未来启用 datagen，代码生成路径会引用不存在的贴图。

**修复方案**：采用独立路径方案（路线 B），为未来侧透版机壳预留独立贴图通道：

1. 创建 12 个 illumination 专用 siding 贴图（4 材质 × 3 形态），初始内容复制自对应普通版：
   - `{material}_illumination_encased_cogwheel_side.png`（4 个，small）
   - `{material}_illumination_encased_cogwheel_side_connected.png`（4 个，CT 精灵表）
   - `large_{material}_illumination_encased_cogwheel_side.png`（4 个，large）
2. 修改 32 个 illumination 齿轮模型 JSON 的 siding 引用为 illumination 专用路径
3. 代码无需修改（`getIlluminationSiding()` 和 `getIlluminationCogCTBehaviour()` 原有路径即正确）

独立路径方案使资源包可分别替换普通版和照明版的侧面贴图，为未来添加侧透版机壳预留了通道。
