## 15. 开发环境配置 GUI 集成与 JEI 版本升级

**日期**：2026-08-25

**问题描述**：配置功能（#14）代码实现完毕并编译通过，但开发者在 runClient 测试时缺少游戏内配置 GUI——无法通过 Mods 页面点击 Config 编辑配置项来验证配置功能是否正常工作。需要引入第三方 mod 作为开发环境运行时依赖，提供配置界面用于测试。此依赖仅用于开发环境，不会打包到发布版本，最终用户不受影响。

**方案调研与选型**：

1. **Better ModList**：最初尝试，但 javap 反编译确认从最早版本 1.0.2 到最新 21.1.1 全部带有 `@SubscribeEvent` 注册到公共事件总线的 bug（`RegisterKeyMappingsEvent` 是 Mod Bus 事件，NeoForge 21.1.152 拒绝此做法），所有版本不可用。

2. **NeoForge 内置 ConfigurationScreen**：NeoForge 1.21.1 内置交互式配置 GUI，但需在代码中注册 `IConfigScreenFactory` 扩展点。此为备选方案（无需额外依赖，但需修改 mod 代码）。

3. **Configured（MrCrayfish）**：最终选用。CurseForge 上的配置 GUI mod，自动为所有注册了 `ModConfigSpec` 的 mod 生成交互式配置界面。作为 `localRuntime` 依赖引入，仅在开发环境 runClient 时加载，不参与编译产物。

**修复**：

1. 下载 Configured v1.21.1-2.6.1 的 NeoForge jar（`configured-neoforge-1.21.1-2.6.1-signed.jar`，428875 bytes）放到 `libs/` 目录
2. `build.gradle` 添加 `localRuntime name: 'configured-neoforge-1.21.1-2.6.1'`（flatDir 方式引用，`localRuntime` 不参与编译产物，仅 runClient 时可用）
3. `gradle.properties` 添加 `configured_version = 1.21.1-2.6.1`，移除 `better_modlist_version`
4. **JEI 版本升级**：Configured 2.6.1 的 `neoforge.mods.toml` 声明 JEI 依赖 `versionRange = "[19.24.0.317,)"`，项目原用 JEI 19.21.0.247 不满足，导致开发环境 runClient 崩溃。将 `jei_version` 升级为 `19.24.0.317`（刚好满足要求的最低版本，最小化版本跳跃风险）。

**runClient 验证结果**（开发环境测试）：

- 游戏完全正常启动，无崩溃
- Configured 2.6.1 成功加载，3 个配置提供者全部注册成功（NeoForgeConfigProvider、FrameworkConfigProvider、JeiConfigProvider）
- Configured 为 crystal_clear 注册了配置工厂：`Registering config factory for mod crystal_clear. Found 1 config(s)`
- 开发者通过 Mods → Config → crystal_clear 打开配置界面，多次编辑并保存 `crystal_clear-client.toml`，触发 `Saving config and sending reloading event`
- JEI 19.24.0.317 正常工作，注册了 2398 个物品

**Configured 依赖关系确认**：

| 依赖 | 类型 | 版本要求 | 项目实际 |
|------|------|----------|----------|
| neoforge | required | [21.1,) | 21.1.152 ✓ |
| minecraft | required | [1.21.1,) | 1.21.1 ✓ |
| framework | optional | [0.9.6,) | 缺失（不影响） |
| jei | optional | [19.24.0.317,) | 19.24.0.317 ✓ |

**文件**：
- `libs/configured-neoforge-1.21.1-2.6.1.jar`（新增，开发环境用）
