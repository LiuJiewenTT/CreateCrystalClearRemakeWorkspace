## C-1. illumination_encased_shaft 引用不存在的模型导致 runData 崩溃

**日期**：2026-09-05

**问题描述**：`GlassBlockBuilders.java` 中 `illuminationEncasedShaft()` builder 的 blockstate 和 item model 代码均引用 `block/illumination_encased_shaft/block` 作为父模型，但 `src/main/resources` 中不存在 `illumination_encased_shaft/` 目录（只有 `glass_encased_shaft/` 目录）。此前因 Gradle 编译缓存（`compileJava UP-TO-DATE` / `FROM-CACHE`）未真正重编译，runData 使用旧 class 文件得以通过；一旦强制 `--rerun-tasks` 重编译后 runData 立即崩溃。

**根因分析**：illumination 包覆轴与 glass 包覆轴的模型结构完全相同（均为立方体外壳 + opening 贴片），区别仅在于 casing 贴图（`_illumination_casing` vs `_glass_casing`）。代码中独立引用 `illumination_encased_shaft/block` 但从未创建该模型文件。

**修复**：改代码复用 `glass_encased_shaft/block` 和 `glass_encased_shaft/item` 作为父模型。模型结构一致，通过 `texture("casing", ...)` 传入 illumination 贴图即可区分外观。在方法上方添加注释说明：illumination 版暂无独立模型计划，若未来需要可创建 `block/illumination_encased_shaft/` 目录并恢复引用。

**同步**：从 gen 同步 4 个 block 模型 + 4 个 item 模型到 main（parent 已指向 glass_encased_shaft）。

**编译验证**：BUILD SUCCESSFUL（含 runData --rerun-tasks）

**文件**：`src/main/java/.../builders/GlassBlockBuilders.java`、8 个 illumination shaft 模型 JSON

## D-1. 小齿轮 item 父模型纹理槽命名与 datagen 代码不一致

**日期**：2026-09-05

**问题描述**：12 个小齿轮 item 模型在 gen 和 main 之间纹理槽命名不一致。gen 用 `1`/`1_2`/`side`（Create 原版命名），main 用 `backing`/`cogwheel`/`siding`（本项目自定义命名）。

**根因分析**：item 模型父模型（`encased_cogwheel/item.json`）的纹理槽命名与 Create 原版不一致。Datagen 代码已写入自定义名称（`backing`/`cogwheel`/`siding`），但 item 父模型此前未更新，导致 gen 产物纹理槽名称不匹配父模型，在游戏内可能渲染黑紫。

**修复**：修改 item 父模型（`encased_cogwheel/item.json`），统一纹理槽命名为 `casing`/`backing`/`cogwheel`/`siding`/`opening`。所有 24 个子 item 模型提供 `backing`/`casing`/`opening`/`siding`，Minecraft 模型解析器会用子模型覆盖父模型默认值。

**Blockbench 预览**：Blockbench "打开父级并应用纹理"功能不生效是 BB 自身 bug。item 父模型保留默认纹理值是合理设计，游戏内行为正确，两个 item 父模型维持现状不做修改。

**编译验证**：BUILD SUCCESSFUL（含 runData --rerun-tasks，gen 产物与 main 一致）

**文件**：`src/main/resources/assets/crystal_clear/models/block/encased_cogwheel/item.json`

## F-1. scaffold item 模型引用不存在的 parent 导致 runData 崩溃 + top 纹理不一致

**日期**：2026-09-05

**问题描述**：`GlassBlockBuilders.java` 中 `glassScaffolding()` builder 的 item model 代码引用 `block/scaffold/item` 作为父模型，但 `src/main/resources` 中只有 `scaffold/block.json` 和 `scaffold/block_horizontal.json`，不存在 `scaffold/item.json`。此前同样被编译缓存掩盖，强制重编译后 runData 崩溃。

此外，item 模型的 `top` 纹理代码用 `getTopTexture(casing)`（返回 `create:block/funnel/{casing}_funnel_frame`），但 main 中所有 6 个 scaffolding item 模型手动改用了 `{casing}_glass_casing` 纹理。

**根因分析**：
1. parent 路径错误：`scaffold/item` 从未创建过。按 mod 开发惯例，item 模型应有独立的 `scaffold/item.json`，但当前缺失。临时复用 `scaffold/block` 作为 item parent（block 模型可同时用于 blockstate 和 item render），后续应创建 `scaffold/item.json` 并恢复引用。
2. top 纹理：代码用原版 Create 的 funnel_frame 纹理（有镂空效果），main 手动改为 glass_casing（封闭玻璃面），两者外观差异明显

**修复**：
1. parent 临时改为 `block/scaffold/block`（WORKAROUND，代码中已注明：正常应创建独立 `scaffold/item.json`）
2. top 纹理改为 `{casing}_glass_casing`（与 main 中的手动修正一致）
3. 代码中添加 TODO 注释记录原始纹理 (`getTopTexture` = funnel_frame) 和未来设计方向

**编译验证**：BUILD SUCCESSFUL（含 runData --rerun-tasks）

**文件**：`src/main/java/.../builders/GlassBlockBuilders.java`

## B-1. casing tag 排序与 replace 字段差异

**日期**：2026-09-05

**问题描述**：3 个 tag JSON 文件（`create/tags/block/casing.json`、`create/tags/item/casing.json`、`minecraft/tags/block/climbable.json`）在 main 和 gen 之间存在 `replace` 字段和 values 排序差异。

**根因分析**：
1. `replace` 字段：main 手动加了 `"replace": false`，gen 不含该字段。NeoForge `TagFile.CODEC` 中 `replace` 使用 `optionalFieldOf("replace", false)`，默认值 `false` 时序列化省略，因此 datagen 永不输出此字段。省略与显式 `false` 运行时行为完全一致，无法通过 datagen 强制输出。
2. 排序：gen 的 casing.json 顺序为 glass → clear_glass → illumination（与 `CPBlocks.java` 注册顺序 `GLASS_CASINGS` → `CLEAR_GLASS_CASINGS` → `ILLUMINATION_CASINGS` 一致），main 旧版为 clear_glass → glass → illumination。用户要求通透玻璃版排在普通玻璃版之后，即 gen 顺序更合理。

**修复**：
- `casing.json`（item + block 两个文件）：排序改为 gen 顺序（glass → clear_glass → illumination），保留 main 手动的 `"replace": false`。
- `climbable.json`：仅 replace 字段差异，无排序差异，保持不动。
- 代码无需修改：`CPBlocks.java` 注册顺序已与 gen 一致。

**文件**：`src/main/resources/data/create/tags/item/casing.json`、`src/main/resources/data/create/tags/block/casing.json`

## H-1. pickaxe.json 缺失 28 个非 pipe 条目

**问题描述**：`src/main/resources/data/minecraft/tags/block/mineable/pickaxe.json` 的 main 版本只有 18 个条目，generated 版本有 56 个条目。main 缺失 38 个条目，其中 12 个为 pipe 条目（阶段六新增，合理），另 28 个为历史遗漏。

**修复**：从 gen 补回 28 个非 pipe 条目，排序与 gen 一致（shaft → cogwheel → large_cogwheel → scaffolding → illumination_casing）。保留 main 已有的 illumination_casing ×4（generated 未生成，类似 G 类手工条目）。pipe 的 12 条随阶段六 pipe 功能提交时一并处理。

**文件**：`src/main/resources/data/minecraft/tags/block/mineable/pickaxe.json`
