## 9. illumination 包覆齿轮侧面贴图路径不一致

**状态**：待定

**描述**：`GlassBlockBuilders.java` 中有两处代码引用了 `{material}_illumination_encased_cogwheel_side` 贴图，但该贴图对所有材质系列（andesite/brass/copper/train）均不存在：

1. `getIlluminationSiding()`（第 382-384 行）：返回 `block/encased_cogwheels/{casing}_illumination_encased_cogwheel_side`，用于 blockstate 模型的 `siding` 纹理。
2. `getIlluminationCogCTBehaviour()`（第 341-342 行）：对非 large 小齿轮引用 `encased_cogwheels/{casingType}_illumination_encased_cogwheel_side` 的 vertical/horizontal CT shift，CT 系统还会拼接 `_connected` 后缀。

然而，所有 36 个 illumination 模型 JSON 手写引用的是 `{material}_encased_cogwheel_side`（不带 illumination 前缀），与 `getSiding()` 一致。

**影响**：当前手写 JSON 优先于代码生成，运行时不会崩溃。但如果未来启用 datagen 重新生成资源文件，代码中的路径会生效并引用不存在的贴图，导致 illumination 包覆齿轮侧面贴图缺失。

**建议**：将 `getIlluminationSiding()` 改为与 `getSiding()` 一致（去掉 illumination 前缀），或将 `getIlluminationCogCTBehaviour()` 改为引用普通 `{material}_encased_cogwheel_side` 而非 illumination 专用变体。

## 6. 大齿轮代码 blockFolder 与手写 JSON parent 路径不一致

**状态**：待定

**描述**：`GlassBlockBuilders.java` 中大齿轮的 builder 代码设置 `blockFolder = "encased_large_cogwheel"`，但手写 JSON 的 parent 路径引用的是 `encased_cogwheel/block`（不是 `encased_large_cogwheel/block`）。资源目录中只有 `encased_cogwheel/` 目录，没有 `encased_large_cogwheel/`。

**影响**：当前手写文件可以正常工作（因为 JSON 直接指定了正确的 parent）。但如果未来运行 datagen 重新生成资源，代码中的 `blockFolder` 设置会导致找不到父模型而出错。

**建议**：后续如有 datagen 需求，修正代码中的 `blockFolder` 或补充 `encased_large_cogwheel/` 资源目录。
