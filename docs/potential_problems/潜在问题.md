## 9. illumination 包覆齿轮侧面贴图路径不一致

**状态**：已修复（阶段五 5.5）

**描述**：`GlassBlockBuilders.java` 中有两处代码引用了 `{material}_illumination_encased_cogwheel_side` 贴图，但该贴图对所有材质系列（andesite/brass/copper/train）均不存在：

1. `getIlluminationSiding()`（第 394-397 行）：返回 `block/encased_cogwheels/{casing}_illumination_encased_cogwheel_side`，用于 blockstate 模型的 `siding` 纹理。
2. `getIlluminationCogCTBehaviour()`（第 351-356 行）：对非 large 小齿轮引用 `encased_cogwheels/{casingType}_illumination_encased_cogwheel_side` 的 vertical/horizontal CT shift，CT 系统还会拼接 `_connected` 后缀。

然而，所有 32 个 illumination 齿轮模型 JSON 手写引用的是 `{material}_encased_cogwheel_side`（不带 illumination 前缀），与 `getSiding()` 一致。

**影响**：当前手写 JSON 优先于代码生成，运行时不会崩溃。但如果未来启用 datagen 重新生成资源文件，代码中的路径会生效并引用不存在的贴图，导致 illumination 包覆齿轮侧面贴图缺失。此外，CT 连接贴图系统也因路径不匹配而未对照明齿轮生效。

**修复**：采用独立路径方案（路线 B），为未来侧透版机壳预留独立贴图通道：
1. 创建 12 个 illumination 专用 siding 贴图（4 材质 × small/large/connected），初始内容复制自普通版
2. 修改 32 个 illumination 齿轮模型 JSON 的 siding 引用为 illumination 专用路径
3. 代码无需修改（`getIlluminationSiding()` 和 `getIlluminationCogCTBehaviour()` 原有路径即正确）

独立路径方案使资源包可分别替换普通版和照明版的侧面贴图。

## 11. 玻璃机壳水管内部铜管不渲染

**状态**：已搁置（用户希望未来实现透视效果，当前暂不处理）

**日期**：2026-09-05

**描述**：玻璃机壳包覆铜水管后，内部铜管不可见。经深入排查确认，原版 Create 的铜机壳包覆水管（`ENCASED_FLUID_PIPE`）本身也不渲染内部铜管——这是原版设计而非 bug。

根因链：
1. `FluidPipeBlock.isPipe(state)` 检查 `state.getBlock() instanceof FluidPipeBlock`
2. `EncasedPipeBlock extends Block`（不是 `FluidPipeBlock`），`isPipe()` 返回 false
3. `shouldDrawCasing()` 返回 false → `FLUID_PIPE_CASING`（3D 外壳）不渲染
4. `StandardPipeFluidTransportBehaviour.getRenderedRimAttachment()` 对 `EncasedPipeBlock` 子类返回 `AttachmentTypes.NONE`，不渲染管道接口

**影响**：玻璃机壳包覆水管后只能看到薄片外壳（`block_flat`/`block_open`），内部铜管不可见。与原版铜机壳行为一致。

**用户意图**：用户希望玻璃机壳能实现原版铜机壳不具备的"透视内部铜管"效果，但当前先搁置以避免工作流杂乱。详见 `docs/future/未来参考选用事项-2026.md`。

**可能的实现方向**：
- 自定义 `FluidTransportBehaviour` 子类不返回 `NONE`
- 自定义 `PipeAttachmentModel` 子类强制渲染 `FLUID_PIPE_CASING`
- 在模型中直接加入铜管 3D 元素
